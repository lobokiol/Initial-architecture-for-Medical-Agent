## 总结

本文档用于验证 **Text2SQL / 问数** 场景下：用户用 **业务缩写** 提问（如 `show me ARS bookings in past 8 quarters`）时，系统能否正确映射到 **数据库字段** 与 **完整业务描述**，并生成可执行的过滤条件（多为 `oh_l4` / `oh_l5` 等组织层级字段）。

### 用例概览（共 19 条缩写）

| 状态 | 缩写 | 说明 |
| :--- | :--- | :--- |
| 映射明确、字段存在 | ARS, ADP, PSP, PCP, SBY, SBTY, VRS, LDO, LCR | 缩写与库字段/描述一致，`数据库返回oh_colums` 多为 1，验证通过 |
| 字段存在但描述需对齐 | SEM, LUS, LLA | SEM 应落 `Services Engagement Manager` 而非缩写；LUS/LLA 需用完整产品名 |
| 描述歧义、多候选 | MSD, LMSD, SBY/SBTY | Service Desk / Sealed Battery 等同义或近义描述需消歧 |
| 库中无对应 oh 字段 | KYD, LDI, LISS, TICRU | 需向用户确认字段或走非 oh 维度 |
| 字段/维度待确认 | SW, SFTW | Software 可能对应 `services_hw` 或 `product_segment_lv1`，易触发多选澄清 |

### 核心问题分类

1. **缩写未展开为全称**：问句含 KYD、LDI、LISS 等时，SQL 未用完整描述（如 `Keep Your Driver`），导致无法匹配库值。
2. **SQL 用了缩写而非库内文案**：如 `UPPER(oh_l4) = 'SEM'` 应为 `UPPER(oh_l4) = UPPER('Services Engagement Manager')`。
3. **描述不在 oh 系列列的标准值中**：部分自然语言描述（Managed Service Desk、Lenovo Live Assistant 等）与 `oh_l4`/`oh_l5` 存量枚举不一致，召回失败。
4. **IntelData / KPI 元数据**：缩写类关键词应带 `type: abbreviate` 与 `special_logic`，且 KPI 不应被拆成多个并列关键词。
5. **同义缩写重复**：SBY 与 SBTY、SW 与 SFTW 需统一映射规则，避免重复或冲突召回。

### 与测试点的对应关系

| 测试点 | 当前主要风险 |
| :--- | :--- |
| 1 描述与缩写一致召回 | KYD、LDI、LISS、SEM 等 |
| 2 IntelData 缩写 KPI | 需覆盖全部 19 条，且 `special_logic` 用全称 |
| 3 KPI 唯一、不拆分 | SW/SFTW、MSD/LMSD 易触发多字段澄清 |
| 4 图表与数据 | 无字段或歧义时易出现空结果或需二次确认 |

### 建议改进（产品 / 知识库）

- **缺字段策略**：KYD、LDI、LISS、TICRU 在知识库标记 `oh_mapping: null`，问数时主动澄清或走备用维度，避免静默空查。
- **歧义合并**：SBY/SBTY → 同一 `Sealed Battery Warranty`；MSD/LMSD → 明确默认 oh 值或单次澄清。
- **Software 类**：SW/SFTW 固定默认字段（或业务规则二选一），减少 `services_hw` vs `product_segment_lv1` 反复追问。
- **回归问句模板**：统一使用 `show me {ABBR} bookings in past 8 quarters`，便于批量对比 SQL 与 `oh_columns` 命中数。
